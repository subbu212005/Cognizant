# Collaborating with Git

Welcome to the **Collaborating with Git** tutorial suite! This repository serves as a hands-on guide to understanding and practicing various team collaboration workflows using Git.

In modern software development, teams use Git to work on the same codebase simultaneously without overwriting each other's changes. To do this effectively, teams agree on specific *workflows* and guidelines.

---

## 📂 Repository Structure & Exercises

This module is split into five practical exercises and reference documents:

1. **[Core Study Notes](Notes.md)**: A theoretical reference guide detailing remotes, branch tracking, syncing, conflicts, and workflow comparisons.
2. **[Exercise 01: Forking a Repository](Exercise-01-Fork-Repository/)**: Learn how to create a personal copy of a repository on a remote server (GitHub/GitLab), clone it locally, and configure it to stay synchronized with the original repository.
3. **[Exercise 02: Creating a Pull Request](Exercise-02-Pull-Request/)**: Understand how to create feature branches, push changes, and request that the project maintainers merge your additions via a Pull Request (PR).
4. **[Exercise 03: Feature Branch Workflow](Exercise-03-Feature-Branch-Workflow/)**: Work with a shared repository model. Learn to write code in short-lived feature branches, keep them clean, and merge them back to the main branch.
5. **[Exercise 04: Forking Workflow](Exercise-04-Forking-Workflow/)**: Explore the popular open-source workflow. Learn how to maintain a fork, sync changes from upstream, use rebase, and submit pull requests.
6. **[Exercise 05: Centralized Workflow](Exercise-05-Centralized-Workflow/)**: Examine the traditional centralized Git workflow where developers commit directly to a single shared `main` branch, and learn how to manage and resolve merge conflicts when pushing.

---

## 🎯 Learning Objectives

By the end of this suite, you will be able to:
- Explain the difference between **origin** and **upstream** remotes.
- Connect a local repository to multiple remote repositories.
- Use branching strategies to organize feature development.
- Confidently push branches and initiate Pull Requests.
- Keep a local repository and a fork synchronized with an active parent project.
- Identify, understand, and resolve **merge conflicts** in git workflows.
- Select and apply the appropriate Git workflow depending on project size and team access constraints.
